## Updates on Phase 4 Integration for ALGOL 26

### Context:
During the implementation of Phase 4 (Concurrency features) for the ALGOL 26 interpreter project, the following issues and resolutions occurred:

1. **ChanDeclStmt**:
   - Errors arose because `infer_type_annotation` was unrecognized in the constraint generator. Resolved this by using the `resolve_type` method for type annotations.
   - Imported missing AST nodes `ChanDeclStmt`, `SendStmt`, `ReceiveExpr`, `SelectStmt`, `AsyncProcDeclStmt` into `interpreter.py`.

2. **Environment Extensions**:
   - Added properties `channels` and `tasks` to the `Environment` class, along with helper methods like `put_channel` and `get_channel`.

3. **Interpreter Runtime Adjustments**:
   - Moved `eval_*` methods for concurrency inside the `Interpreter` class.
   - Adjusted `eval` dispatch method for new AST nodes.

4. **Scheduler Integration**:
   - Implemented a `Scheduler` class and integrated it into the `Interpreter` to support task scheduling and cooperative multitasking.

### Current Status

### Lessons & Adjustments
- Top-level declarations order matters: parser must place `chan` declarations into `declarations` list, not `statements`, so they're processed before statements that reference them (including inside async procs).
- Typechecking of `AsyncProcDeclStmt` must not use non-existent `infer_block`; instead loop statements manually.
- `default_value` utility must correctly inspect `type_obj` (e.g., `PrimitiveType.name`).
- `FunctionType` uses `return_type`, not `ret_type`.
- Chat debugging revealed importance of systematically checking parser grammar vs typechecker environment population order.
